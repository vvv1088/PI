# 拆文件与最简构建方案(P2 前必须 · 等 V 拍板)

> 2026-08-11 出稿。现状:index.html 已 3100+ 行 / 430KB 内联 JS + 8 个 mis-*.js。
> 痛点:①单文件改动冲突风险高;②review 靠肉眼滚屏;③版本快照整文件复制;④新功能被迫塞进新外挂文件,内聚性越来越差。

## 方案 A(推荐):零依赖拼接构建

**思路**:源码拆目录,构建 = 一个纯 node 脚本按序拼接,产物与现在的单文件完全同构——浏览器看到的东西不变,cPanel 发版方式不变。

```
mis-ui/
  src/
    index.template.html   ← 骨架:HTML + CSS + <!--INJECT:core--> 等注入点
    01-core.js            ← 工具/auth/导航/权限(esc/fmtTs/go/can…)
    02-ci.js              ← Competitor Intelligence 六视图
    03-planning.js        ← Idea/Hypo/Creatives/Dict/Monthly
    04-budget.js          ← Budget + 分工
    05-admin.js           ← Roles/Users/Audit(MIS 侧)
  mis-*.js                ← 现有 8 个文件原样保留,不动
  tools/build.js          ← ~40 行 node:读 template,把 src/*.js 按序注入 <script>
  dist/index.html         ← 构建产物 = 发版文件
```

- **构建命令**:`node tools/build.js`(无 npm 依赖,3 秒内)。冒烟脚本改跑 dist。
- **版本纪律升级**:快照 = git(src 天然分文件 diff),`versions/` 只留 dist 里程碑。
- **发版不变**:dist/index.html + 8 个 mis-*.js 上 cPanel。

## 方案 B:esbuild 真模块化

import/export、压缩、sourcemap。工程上更正统,但引入 node_modules 依赖与调试映射复杂度,和"静态站+人肉上传"的发版现实不匹配。**不推荐现在做**,P3 若上 CI 再议。

## 迁移步骤(方案 A,预计 1–2 个版本)

1. 纯搬运:index.html 内联 JS 按上述五块切进 src/(**零逻辑改动**),每搬一块跑一次全量冒烟;
2. build.js + template 就位,dist 产物与手工版逐字节比对(除注释行);
3. 全量冒烟 + demo 重生成走 dist;
4. 之后所有改动落 src/,`versions/` 纪律切换。

**风险与对策**:一次性大 diff → 用"逐块搬 + 每块冒烟"分散;搬运窗口内(约半天)冻结其他 index.html 改动。

## 需要 V 决定

1. 方案 A / B(建议 A);
2. 何时开搬(建议:线 B patch 部署、live 联调这些外部节点的空档期做);
3. 五块切分粒度是否 OK(可再细,粒度越细 diff 越友好)。
