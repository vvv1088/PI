# MIS — 用透明代替汇报（协作阅读指南）

> 本文档不介绍具体操作（操作请见 User Guide），而是说明：这套系统如何让 Marketing 的工作过程对 USC 与决策人完全可见，从而减少例行沟通的成本。
> 适用对象：USC 团队、决策人，以及任何需要了解广告投放进展的同事。最后更新：2026-07-08

---

## 1. 为什么需要这份文档

| 传统协作方式 | 局限 |
|---|---|
| 会议同步进展 | 占用双方时间；信息传递依赖现场理解，容易出现偏差 |
| 口头 / 消息更新 | 缺乏统一记录，时间一长难以追溯，各方印象可能不一致 |
| 需要数据时逐次询问 | 等待回复、往返确认，信息始终滞后 |
| 人员交接 | 过往测试的背景与结论依赖个人记忆，交接成本较高 |

MIS 的方式：**Marketing 的每一步都记录在系统中**——想法、假设、素材、排期、花费、结论、预算，全部结构化、有留痕。因此：

- 想了解任何情况，**打开系统即可看到**，无需等待汇报；
- 需要关注的事项，**Slack 会在关键节点主动通知**；
- 会议专注于真正需要讨论与决策的事项，**不再用于同步信息**。

## 2. 一条广告的完整链路（全程可追溯）

每条广告都有完整的血缘链，每一环都有编号、可以点开查看：

```
IDE-012 想法          「竞品在推真人荷官短视频，我们尚未测试」（来源：竞品情报，AI 从周报提炼）
   │  立假设
   ▼
HYP-045 假设          品牌 OK188KH · 顾客阶段：拉新 · 人群：高价值玩家 25-40
   │                  测试维度：仅测 Hook（信任 vs 优惠），其余维度全组锁定
   │                  指标：7-Day High-Value Rate 8% → 10% · 排期 7/12 起测 7 天
   │  配素材
   ▼
CRT-101 / CRT-102     两条素材，仅 Hook 不同（系统校验保证其他维度完全一致）
   │  上线投放
   ▼
每周花费 / FDC 回填    Creatives 页可见；Budget「已投放」自动累计
   │  测试期到
   ▼
判定                  结论：成立 · 结论沉淀：信任类 Hook 对高价值人群 FDC -23%
                      → 进入 Results，胜率自动统计；下月可转为主力运行
```

> 上例为示意（编号虚构）。**任何时点查看，都能回答**：它源自哪个想法 → 为什么这样测 → 测试变量是什么 → 目标人群是谁 → 对应哪个顾客阶段 → 花费多少 → 结果如何。

## 3. 想了解什么 → 在哪里查看

| 以前需要开会确认的 | 现在的入口 | 可以看到 |
|---|---|---|
| 本月的投放计划是什么？ | **Monthly Overview** | 每品牌一卡：预算、该月全部排期测试（按顾客阶段分组）、素材就绪度 |
| 这条广告为什么做？ | **Hypotheses** 打开该假设 | 源自哪个想法（IDE 编号）、起因、证据（"纯直觉"也会如实标注） |
| 它的测试变量是什么？ | 假设的**测试维度** + 对比页 | 仅变 Hook / 仅变 Format 等；系统校验保证"只变声明的维度"，结论才可信 |
| 目标用户画像是什么？ | 假设详情的**人群 / 年龄段** | Persona + Age Range，立假设时即已声明 |
| 对应哪个顾客阶段？ | 列表 **Stage 列**（分色） | 拉新 / 激活 / 留存 / 复购转化 / 唤回 |
| 何时上线？测多久？ | 假设排期 + Creatives **Schedule 列** | 预计上线日 → 结束日，自动倒数 |
| 预算使用情况如何？ | **Budget Allocation** | 申请 / 核批 / 最终额、已投放（按周花费自动汇总）、使用率 |
| 这笔预算如何确定的？ | **Budget 行的「历史」** | 谁在何时填写了什么、理由为何、由谁最终决策——完整时间线 |
| 测试结果如何？ | **Results** / 假设的判定 | 结论 + 置信度 + 沉淀的经验 + 各类假设胜率 |
| 竞品近期动态如何？ | **Weekly Summary** | AI 每周自动生成的竞品报告（很多测试方向即来源于此） |

## 4. 关键节点的主动通知（Slack）

无需持续查看 dashboard——关键节点由 MIS Bot 推送至对应频道，并 @ 相关负责人：

| 时机 | 推送内容 |
|---|---|
| Marketing 确认发送月计划 | 该品牌完整当月计划（预算 + 按阶段分组的测试清单） |
| 核批金额低于申请 | 「预算待决策」@决策人 |
| 预算最终确定 | 「预算已定」cc 申请与核批双方 |
| 每天 09:00 | 到期未判定 / 应上线未上线 / 效果告警，@ 对应 owner |
| 每月 20 / 23 / 26 / 29 | 预算瓶颈催办：每品牌只催"当前卡住的一步"（申请→核批→决策），@ 对应负责人 |
| 每月 25 / 27 / 30 | 发送计划催办（@ 各品牌 Marketing 负责人） |

**推送负责"信息找人"，dashboard 负责"人找信息"**，两者配合，日常同步无需会议。

## 5. 透明的前提：三个例行动作

系统的透明度，依赖 Marketing 将以下动作及时记录在系统中（均为轻量操作）：

| 动作 | 时机 | 缺失的影响 |
|---|---|---|
| 填写排期（上线日 + 测试周期） | 立假设时 | 计划对他人不可见，每日提醒也无法生效 |
| 记录每周花费 | 每周投放后 | 预算「已投放」数据失真，需额外核对 |
| 测试结束及时判定 | 测试期到期 | 结论未沉淀，经验无法复用 |

> 换个角度说：**记录在系统中，即视为完成汇报**。这三个动作到位后，例行的进展同步会议即可省去。

## 6. 仍需要面对面沟通的场景

透明化替代的是"同步信息"的会议，而非全部会议：

| 场景 | 形式 |
|---|---|
| 月度计划审批 | 与 V 进行一次 meeting，通过后由各品牌负责人在系统中「确认发送」 |
| 预算分歧的最终决策 | 决策人在系统中完成决策（讨论过程可在线下或 Slack 进行） |
| 字典维护 | 月会根据实际使用增删标签取值 |

区别在于：**会前各方已经看到同一份事实**，会议只需讨论"怎么办"，无需再花时间同步"是什么"。

---

## 7. 总结

> **过去**：完成工作 → 安排会议 → 口头说明 → 效果取决于对方当下的理解与记忆。
> **现在**：工作记录在系统中 → 相关人员随时查看、Slack 主动推送 → 有编号、有留痕、有数据，任何人接手都能完整了解。
